EI_Content_Agent

A research partner and domain expert that helps develop Education Informatics as a discipline. It writes papers, gathers and verifies material, and discusses ideas. Every valid finding is recorded in a literature database and a structured wiki, so the field accumulates knowledge instead of re-deriving it.

How it works

You just talk to it. Anything new you mention (a topic, an idea, a DOI, a PDF) runs through the same loop, which leaves the knowledge base better structured than before.

  1. Prompt"I heard about…", a DOI, a PDF or an idea
  2. ResearchLocal literature, DOI registry, web search
  3. RecordCSV row with APA, BibTeX, summary, status
  4. StructureWiki pages linked to the six criteria
  5. LearnLasting judgements go into the skills
  6. CheckValidate, rebuild the index, export for Zotero. A session-start hook backs up the CSV.

Structure

Three kinds of store. What is learned lives in exactly one of them.

Private · Nextcloud

Literature database

One CSV, ei_literature.csv, is the single source of truth. Only scripts/eidb.py writes it; a hook blocks direct edits.

  • backups/: one copy per session
  • exports/: library.bib, library.ris for Zotero
  • drafts/: papers and proposals
Public · GitHub

Wiki: what is known

Concepts, approaches, methods, propositions and the field-level argument. Each claim cites the database with [@citekey].

  • discipline/: definition, criteria, uniqueness, rivals
  • approaches/: characteristics grid
  • log.md: what changed, per session
Public · GitHub

Skills: how to work

Workflows and recurring judgements (e.g. "measure the room, not the child"). ei-learn keeps them current as the field develops.

  • CLAUDE.md: persona, routing, standing rules
  • templates/: page types, proposal outline

Example: two prompts

I heard about data-based approaches for education.
  1. ResearchLocal literature, Crossref search, web search; reads abstracts and PDFs.
  2. Recordeidb.py add --doi … for each source: APA, BibTeX, summary, status, criteria.
  3. StructureWrites wiki/approaches/data-based-approaches.md with the 13-characteristic grid.
  4. PropagateRival fields, criteria board, uniqueness argument, open questions, log.
I heard about learner portfolios from the UK.
  1. Check firstFinds existing entries and pages; updates instead of duplicating.
  2. RecordNew UK sources added; duplicates detected by DOI and title.
  3. Structureapproaches/learner-portfolios.md placed on the same grid; the grid grows if needed.
  4. LearnLasting judgements go into a skill; the wiki index and .bib/.ris are regenerated.

The literature database

One row per reference. Bibliographic data come from the DOI registry, so the agent never types a reference from memory.

Columns

id type authors year title venue volume issue pages doi url apa bibtex summary topics ei_criteria ei_role wiki_pages source_status verified_via local_file added_on added_by_query notes

Evidence status

  • P: primary text read in full
  • R: cited in the anchor paper, not re-read
  • S: DOI record or abstract only
  • D: from the user's notes or slides
  • M: from model memory, unconfirmed
python3 scripts/eidb.py search "Kane 2013 validating interpretations"
python3 scripts/eidb.py add --doi 10.1111/jedm.12000 --summary "…" --criteria methods --role method --status S
python3 scripts/eidb.py list --criterion methods        # evidence for criterion C5
python3 scripts/eidb.py sync && python3 scripts/eidb.py validate
python3 scripts/eidb.py export                          # library.bib / library.ris → Zotero

The discipline lens

Every source and page is tagged with the six criteria of disciplinarity adopted in the anchor paper (Tegelbeckers & Bünning, 2026). The standard critique that a new field lacks a method of its own targets C5. The agent's working answer is a specific combination (decision record, decision-value test, expiry as data). It is labelled as a proposal, not a finding.

C1 Objectspecified
C2 Knowledgenot satisfied
C3 Theoriespartly
C4 Terminologypartly
C5 Methodspartly
C6 Institutionsnot satisfied

Setup

git clone https://github.com/OVGU-VET-TechEd/EI_Content_Agent.git && cd EI_Content_Agent
cp ei.config.example.json ei.config.json   # set data_dir and literature_dirs
python3 scripts/eidb.py init
claude                                     # start the agent here

Privacy: the database, backups, exports, drafts, PDFs and notes never enter git. The CI checks this. The wiki is public, so it never contains personal or career details or unpublished third-party material.
